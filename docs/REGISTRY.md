# Public Registry / Private Overlay

Sources: data/public/vendors/*.json. Human-edited source files are authoritative; registry.compiled.json is generated by schema → conflict validation → compile. Exact model matching is vendor scoped. Alias compatibility must have manufacturer proof; a plausible nearby model is not an alias.

Top-level fields: id, name, aliases (brand names), domains, classification, provenance, verified_at, noise_tokens, model_aliases, models, rules, ecosystems. The complete strict Schema is [../schemas/vendor.schema.json](../schemas/vendor.schema.json).

Model/ecosystem record: id, canonical_page, status, verified_at, provenance, support_mode, supported_models, excluded_models; optional model, successor, rule_id, software_kind, max_age_days. Dates use YYYY-MM-DD; default freshness 180 days. Future or old dates cannot authorize fill. Lifecycle active is the only auto-fill state. Successor is a relation, not an instruction to automatically use another product's driver.

support_mode exact uses an exact model record. explicit-model-list requires an exact supported_models match. family-rule requires the matched rule_id; do not turn a software vendor homepage into blanket brand compatibility. Explicit exclusions take precedence.

Official domains match exact host or its child only; registering support.example.com cannot grant example.com or example.com.evil.com. Regional hosts can be added to domains. Delegated hosts additionally require the independently fetched exact-model official page to link to the destination. A string called delegated_by is not proof.

Noise tokens are documented per Vendor. Default normalization retains colour, bracket/spec text and all support-relevant suffixes. Only fields shown to be irrelevant to the vendor's model/support identity should enter noise_tokens.

Scoped model alias: from, to, status (confirmed/needs-refresh), provenance. Only independently proven confirmed aliases affect canonical_model. Unknown legacy regional equivalences are not shipped. Public source schema supports PUBLIC_SOURCE_ONLY or SYNTHETIC; UNKNOWN rejects public validation.

To add a vendor, start from [../examples/vendor.example.json](../examples/vendor.example.json). It is a SYNTHETIC test vendor, not a claim about a real manufacturer. The schema and exact/offline lookup are tested by the same fixture data. Add publicly permitted source URLs and actual verification dates for a real Vendor, then run registry validate/build and tests.

Current migration holds 1,549 catalogue mappings and 31 regional aliases in the immutable sibling source archive. 56 generic policies, 14 passive exclusion rules and 3 brand markers were projected through explicit field allowlists; all private identifiers, aggregate-company evidence and source notes were removed. Two exact public pages were independently fetched and verified. Unverified shared software records are needs-refresh. Adding a new lifecycle claim requires evidence beyond HTTP 200.

The source bundle is not part of release ZIPs. Review redistribution rights for old code/generalized policy definitions before selecting a public license. The package does not claim permission to publish the source catalogue.
